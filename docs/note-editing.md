# 笔记人工修订

本模块在既有不可变笔记上追加人工版本。原 AI 版本、来源快照和证据保留；保存人工版本不发送平台请求或模型请求。
代码与真实验收状态见 PROGRESS.md，本文的接口描述不等于生产门禁已通过。

## 使用方式

在账户的知识笔记中打开笔记，选择最新版本并开始人工修订。可以修改标题、概述和已有结构化条目的文字，
证据编号保留；个人理解独立填写并明确标注未经来源核验。结构化内容与 Markdown 由同一文档生成。
人工修改可能改变原观点的含义，引用编号有效只代表片段存在，不能证明修改后的观点受到证据支持。

保存会生成下一版本。旧版本仍可查询和下载。若其他成员已保存更新版本，当前保存返回冲突，草稿保留；
用户须先复制需要保留的草稿，再明确放弃草稿并打开最新版本，重新修订时自行合并内容。
断网后重试使用同一个幂等键，改变草稿会创建新键。

## 接口与边界

`POST /api/v1/spaces/{tenant_id}/notes/{note_id}/revisions` 先验证当前身份、成员和租户事务上下文。
输入包含 `idempotency_key`、`base_revision_id`、`title`、`overview`、`sections`、`personal_notes`。
不接受客户端的来源快照、生成 run、Markdown、限制说明、证据引文或覆盖统计。

API 与同源 BFF 仅为该 POST 路径允许 128KiB 请求体；包含幂等键和基准 ID 的规范化紧凑 JSON 输入另受 64KiB UTF-8 限制，
个人理解最多 4,000 字符。已有结构化标题、条目、类别和证据数量限制继续生效。
服务端从不可变快照构造证据和来源范围说明，引用只能选择实际提供的证据编号。

固定追加迁移 `0016_note_edits` 区分 `ai_generated` 与 `user_edit`。人工修订不创建伪造的 AI run。
幂等键绑定操作者和请求摘要；同键更改内容返回 `IDEMPOTENCY_CONFLICT`，
基准不是最新版本返回 `NOTE_REVISION_CONFLICT`。写入、章节、证据与 `notes.edited` 审计同事务提交。
数据库保留 FORCE RLS、复合外键和追加权限，不能修改或删除历史版本。
每空间每个UTC自然日最多20次人工修订，全空间所有笔记版本最多1,000份；同键重放不重复占额。
页面版本列表显示最近20项，历史数据保留。

本模块不包含逐字差异、自动合并、标签、语义检索或平台正文自动获取。B站 HTTP412、Ollama 暂缓、
生产资源与漏洞门禁仍按实际证据记录；人工修订不构成新的模型验收。
