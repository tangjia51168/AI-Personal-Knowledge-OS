# 公开内容采集、快照与证据笔记

本模块沿用最初方案的“来源 → 内容快照 → 证据 → 结构化笔记与 Markdown → 修订历史”。
首次交付保留真实能力边界；全文、字幕、评论与弹幕不混成同一种内容。完整产品路线仍见 PROJECT_SPEC.md。
后续0017为笔记添加人工主题/标签、关联状态和列表分类筛选，分类不改写不可变修订或证据；
接口与权限见[manual-note-labels.md](manual-note-labels.md)，不将人工分组视为知识图谱或自动推断关系。

## 安全连接与独立 Worker

默认 `COLLECTOR_ENABLED=false`。显式开启后，成员逐次同意才能创建 `source_collect` 持久化任务，
沿用真实任务中心、DB outbox、Redis、独立 Celery Worker、配额、取消与状态查询。
客户端只提交来源 UUID 与幂等键；Worker 重新验证真实请求人、会话适用的成员状态和任务归属，
在网络前后分别复核权限/任务尝试，网络期间不持有数据库事务或锁。

连接器每一跳只允许公网 HTTP/HTTPS 的 80/443 端口，拒绝凭据、本地/私网/保留地址与 IPv6 转换网段。
DNS 所有结果必须通过，实际 TCP 连接固定到已经检查的 IP，TLS 仍校验原域名与 SNI；不使用环境代理。
重定向最多 3 次、禁止 HTTPS 降级，每跳重新校验；总时限 20 秒，原始响应最多 1MiB，正文最多 60,000 字符。
拒绝压缩响应，不加载图片/iframe/样式或其他子资源。受限网络出口仍是生产纵深防御要求。

固定迁移 0013 增加 append-only `source_snapshots`，每条绑定租户、来源、采集任务、版本和创建人。
采集快照保存最终获取地址、真实原始响应 SHA-256、提取文本、平台字段与局限，不把提取文本称为完整原网页存档。
0015通过provenance区分人工导入：其URL只表示关联来源，摘要对应用户原UTF-8输入，不是远端响应。
同一成功任务只能产生一条快照；独立重采集产生新版本。FORCE RLS、复合外键与 INSERT 策略共同验证归属，
运行角色只有 SELECT/INSERT。空间最多 1,000 条快照，沿用每日 100 个任务、同时最多 10 个任务限制。

## AI 总结与证据

快照详情中的“生成笔记”是显式同意的真实模型请求。初版总结仅支持租户已配置、运维已开放的 DeepSeek，
不把全局 `.env` 密钥自动复制给用户，不跳过首选本地模型或自动调用其他云供应商。
固定官方端点、非流式 JSON、关闭思考模式、单次总期限60秒、输出最多 2,048 Token；
输入只取有限证据前缀并记录覆盖范围。BFF总结总期限135秒，网关140秒。
不自动重试；同一幂等键查询已有结果，pending/unknown 状态禁止换键重复提交同一快照。
初版通过有界同步 API 调用完成生成，未接入自动重放的 Celery 任务，避免故障重放导致重复付费。

快照切成连续编号、最多 800 字符的真实原文片段。每个结论必须引用已发送的编号；服务端验证结构、
编号、唯一章节与输出安全，然后从同一结构渲染 Markdown，保存模型原文以外的经过验证的文档。
引用有效只证明编号对应快照，不能证明推理正确或绝不遗漏；界面与下载内容明确这一点。
仅元数据快照必须说明未取得字幕，不能把视频标题推断成视频教学步骤、时间点或完整总结。

固定迁移 0014 增加 `note_runs`、`notes`、`note_revisions`、`note_sections`、`evidence_items`。
调用前持久化 pending 声明，使用每日 20 次总结与现有模型用量预留；未知请求保留 reserved 用量。
真实 Token 入库，无法获知账单费用时保持 null。终态不可重置；内容按版本追加、保留快照与引文关系，
历史版本可查看与下载 Markdown。0016增加人工修订、个人理解和基于最新版本的冲突检测，
详情见[note-editing.md](note-editing.md)；人工保存不调用模型。标签、图谱、RAG、学习与调度仍未实现。

来源与笔记列表现支持关键词、来源URL类型及状态/版本来源筛选，服务端按创建时间和UUID有界分页。
笔记先选定最新版本再匹配，避免旧版命中；筛选不访问平台或请求模型。
人工修订期间保留草稿，保存后按原条件重新读取首页。接口与实时分页边界见[source-note-filtering.md](source-note-filtering.md)。

## 验收方式

- `./scripts/check.ps1`：单元、类型、lint 与前端生产构建。
- `./scripts/acceptance.ps1 -Hardened -RestartCheck`：独立测试库真实迁移、租户权限、队列、存储和重启。
- `python -m scripts.knowledge_acceptance --acceptance`：指定公开链接 → API → 独立 Worker → 真实快照。
- 只有收到新的费用授权后才加 `--allow-paid-requests`；脚本使用固定 DeepSeek 模型，持久化次数与预算账本，
  请求前记账，最多 3 次/每次输出 2,048 Token/保守预留合计不超过 ¥1，未知结果不重试。
  预算是根据官方峰时单价与保守 Token/汇率上界计算的验收预留，不伪装实际账单。

验收仅操作隔离 acceptance 项目；最后清除测试租户加密密钥、撤销会话、恢复运维开关。
快照/笔记/用量保留供恢复与审查，Markdown 另存本机 `.cache/knowledge-real-acceptance/`。
实时结果、失败平台与报告路径以 PROGRESS.md 顶部为准。协议夹具通过不等于平台或模型真实请求通过。
