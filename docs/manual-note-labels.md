# 人工主题与标签

本模块为当前空间内的笔记提供人工分类，由空间的有效成员创建、关联和移除；主题层级见[主题层级](topic-hierarchy.md)，标签仍为平面分类。
不调用模型、采集平台或推断知识关系。真实交付状态及验收证据见PROGRESS.md，本文描述接口和边界。

## 使用

在知识笔记中打开一篇笔记后，可以创建主题或标签，再将其关联到当前笔记；也可以选择空间已有分类。
分类归属于笔记，而非某一修订。查看旧版本、追加人工修订或重新总结时，分类仍适用于该笔记；
移除关联不修改正文、证据或历史修订。不支持合并或物理删除分类定义；目录维护支持主题上级、重命名和可逆归档/恢复，归档不会删除历史笔记关联；筛选仍仅匹配明确关联的分类。

笔记列表可以按一个分类筛选，并与关键词、来源类型、最新版本来源组合。
应用或重置条件回到第一页；页面显示已应用条件。人工修订期间应先保存或放弃草稿再修改分类或筛选。
分类调整后保留打开的详情，按已应用条件刷新列表；笔记可能因关联被移除而离开当前结果。

同一标签仅表示人工分组，不代表两篇内容存在因果、支持、反驳关系或经过核验；目前不提供图谱或模型置信度。

## 输入、配额与一致性

- 名称采用Unicode NFKC和空白合并，去除首尾空白；名称最多60字符、240字节UTF-8，不接受控制或隐藏格式字符。
- 同一空间、同一类型内按规范化名称及casefold键去重；重复创建返回原分类，不产生新审计。
  同名主题和标签可分别存在，不同空间独立保存。
- 每空间最多100个分类，每篇笔记最多20个有效关联；变更受现有身份/IP动作限流约束。
- 关联和移除按目标状态幂等；重复PUT或DELETE不新增审计。关联记录停用后保留，再次关联启用原记录。
  多个成员同时修改时按数据库事务串行提交，最后成功的状态生效；页面刷新读取当前状态。
- 定义可通过带版本校验的维护接口修改名称/状态，关联只允许更新状态、最后操作者与更新时间，不允许应用角色改写归属或删除记录。
- `GET /api/v1/spaces/{tenant_id}/labels/manage`：返回包含 `active`、`version` 和 `updated_at` 的完整目录，供人工维护使用。
- `PATCH /api/v1/spaces/{tenant_id}/labels/{label_id}`：请求至少包含 `name` 或 `active` 及 `expected_version`；旧版本返回409，重名返回409。归档分类不能新关联，恢复后可继续使用。

## 接口与数据隔离

- `GET /api/v1/spaces/{tenant_id}/labels`：返回空间分类，`data`数组有界于100条。
- `POST /api/v1/spaces/{tenant_id}/labels`：`{"kind":"topic|tag","name":"名称"}`；返回已有或新建分类。
- `GET /api/v1/spaces/{tenant_id}/notes/{note_id}/labels`：返回当前笔记的有效分类。
- `PUT /api/v1/spaces/{tenant_id}/notes/{note_id}/labels/{label_id}`：关联到笔记，返回当前分类。
- 同一路径的`DELETE`移除关联，返回当前分类。
- `GET /api/v1/spaces/{tenant_id}/notes?label_id={uuid}`：仅返回具有该有效关联的笔记。
  UUID不能授予权限；无匹配分类时不暴露其他空间数据。游标锚点必须满足分类和其他全部条件，否则404。

所有接口先验证身份和有效成员，再设置事务租户上下文。写入使用已有授权事务与租户锁，锁后复验成员、会话及用户状态，
同时提交分类变更和固定词表审计；审计不含分类名或笔记正文。BFF仅放行这些精确路径/方法，
`label_id`仅转发至笔记列表的精确GET路径。

固定增量`0017_note_labels`增加`knowledge_labels`和`note_labels`两表；`0021_label_management`追加目录状态、乐观版本和更新时间。
FORCE RLS及租户复合外键绑定分类、笔记和成员；应用角色无BYPASSRLS、无删除或归属/类型改写权限；0022后定义和关联仅有指定列更新权限，定义更新需绑定当前成员。分类筛选使用EXISTS，不因多标签而重复结果或新增逐笔记查询。目录维护细节见[label-management.md](label-management.md)。

本模块不证明B站采集、视频理解、Ollama、向量隔离、RAG或生产发布条件通过；这些条件分别保留验收状态。
