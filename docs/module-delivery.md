本机页面 `/progress` 是人工维护、随Web版本构建的工程交付看板，不是在线任务进度或租户统计。
它展示12条产品主线的实际状态、当前实施主线，以及已验收模块的结果、查看步骤、当时基线及局限。
不把测试数量折算为产品完成百分比，也不把一个本机模块通过标为完整Phase 0/Phase 1通过。

## 查看方式

- 首页导航或账户页点击「项目进度与成果」/「查看项目进度与模块成果」。
- 按状态查看主线，展开成果卡片的「查看结果与验收边界」。
- 从主线卡片查看关联交付，或使用「按项目主线查看成果」筛选。基础问答已有相关卡片；没有关联成果的主线显示真实空态，同一能力服务多主线不重复计为总体进度。
- 「打开…功能入口」进入 `/account#明确功能锚点`，登录后定位到对应模块。
  尚无笔记或链接时按真实空态展示，不自动创建数据、登录、采集或调用AI。
- 工程CLI（恢复/归档/扫描）不从浏览器执行；卡片只说明仓库文档位置。
  看板不读取 `.cache`、环境文件、本机日志或运行凭证，不提供文件下载/任意路径接口。

主线和历史成果源位于 `apps/web/src/lib/project-progress.ts`，由页面静态消费。
记录更新日期不是服务检测时间。历史检查数量仅代表各模块交付时的证据，不能覆盖新镜像。
首页实时健康检查与看板分开；看板只消费静态工程记录，其他新业务/schema和真实验收见最新PROGRESS。

## 后续每模块交付约定

可维护性是所有模块的持续验收条件，详见[维护清单](maintenance.md)。用户暂缓项单独记录，不以暂缓取消本模块自动回归或生产门禁。

1. 开始前读最新PROGRESS/ARCHITECTURE/TASKS，按用户要求选定一条主线的连续实施范围。既有模块作为维护单元依次实现，避免跨主线重构；不能把当轮阶段交付记为整条主线完成。
2. 实现并做实际检查，保留失败证据；真实服务缺失则标未验收，不能用协议夹具冒充外部实测。
3. 同步更新PROGRESS、TASKS、必要CHANGELOG和项目总览；更新看板主线/成果能力、基线、局限和固定功能入口。
   验收未通过前不增加“已验收”卡片。
4. 有页面变化时从真实构建生成截图，交付中给出可点击入口及截图；只截取安全区域，不包含密码、令牌、
   邮件链接、模型密钥或用户私人内容。测试内容明确标“协议夹具，无模型/平台请求”。
5. 执行记录守卫、类型/lint/构建及相关浏览器测试。新镜像没有重新扫描时明确说明；无schema变化不宣称重新恢复。

截图是交付辅助证据，不是长期在线数据或平台/模型真实成功凭证。
首次本轮截图保存在工作区忽略的 `.cache/module-results/`（Playwright的工作目录是 `apps/web`）。
后续可新增独立文件名，保留历史结果，不覆盖此前验收日志。

账户功能锚点仅允许固定词表；邮件verify/reset片段依旧立即从地址移除并须手动确认，不持久化令牌。
登录后DOM就绪再定位，未登录不把功能锚点误判为邮件链接。
实际检查以PROGRESS顶部为准；旧模块恢复、CVE及生产暂缓边界不随本看板变成通过。
