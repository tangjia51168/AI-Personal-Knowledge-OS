# 来源与笔记筛选

收件箱和知识笔记支持服务端关键词筛选及游标分页，每页默认20条，最多50条。
筛选只读取当前空间数据库，不访问来源平台或调用模型。实际验收见PROGRESS.md。

## 使用

填写关键词、来源类型和状态后点击应用，结果注明已应用的条件。修改表单不会改变已显示结果的含义；
应用或清空条件会回到第一页。可上一页、下一页，刷新从当前已应用条件的第一页开始。
人工修订期间保留草稿，先保存或明确放弃再切换列表条件。保存后列表按原条件重新查询，
已打开的笔记详情继续保留；新版本不匹配条件时可能从列表消失。

来源关键词匹配原始或规范URL，状态区分已接受与已拒绝。来源类型根据规范URL的域名识别，
包括网页、B站、YouTube、抖音、小红书、知乎；此处识别不代表支持采集或采集成功。
拒绝项没有规范URL，因此不归入任何来源类型；选择类型会排除拒绝项。
笔记关键词匹配最新版本的标题及Markdown正文，可按最新版本的模型生成/人工修订筛选；
来源类型按关联来源URL识别，不受人工导入快照的内容类型影响。
正文按已保存的Markdown文本匹配，其中格式转义字符也属于文本；目前不提供分词或去除Markdown标记的全文检索。

## 接口与一致性

- `GET /api/v1/spaces/{tenant_id}/sources`：`q`、`platform`、`status`、`cursor`、`limit`。
- `GET /api/v1/spaces/{tenant_id}/notes`：`q`、`platform`、`origin`、`label_id`、`reading_status`、`review`、`cursor`、`limit`。
  `label_id`由后续0017人工分类模块追加，须为UUID，与其他条件组合；见docs/manual-note-labels.md。
  个人学习筛选与复习清单复用0020，四状态/未记录和到期/未来提醒语义见[维护入口](learning-review.md)。笔记列表API禁止额外字段，BFF拒绝未知/重复参数；来源接口保持原契约。
- 两者返回`data`数组和`next_cursor`，末页为null。关键词去除首尾空白，最多120字符/480字节UTF-8；
  `%`、`_`和反斜杠按普通字符匹配，大小写匹配遵循PostgreSQL的ILIKE规则。
- 身份、成员及租户事务/RLS先行；UUID游标必须在当前空间及所有当前筛选条件下可见，
  否则404 `SOURCE_CURSOR_NOT_FOUND`或`NOTE_CURSOR_NOT_FOUND`。游标不授予访问权限。
- 按来源或笔记不可变的创建时间、UUID倒序，以末条为后续页边界。笔记最新版本在过滤前选出，
  旧版匹配不会使当前笔记命中。一次有界查询取列表，不逐笔记查询版本。

分页读取实时数据，不固定跨请求快照。新增或修订可能改变结果；游标笔记不再匹配时，
应使用原条件刷新第一页。页面不提供总数、相关度排序或跨页一致性保证。
原筛选模块无迁移，不改变快照、证据或历史版本；主题/标签已由0017独立消费者增量实现，
向量检索与RAG仍待后续模块。不同schema的验收证据以PROGRESS.md最新记录为准。
